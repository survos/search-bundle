# Review: Elasticsearch and InstantSearch usage (2026-10-04)

Context: Elasticsearch became the default engine on 2026-09-15 (see [engine-selection.md](engine-selection.md)). This
review asks whether the code that was shaped while Meilisearch was the main engine is still right, and whether we use the
current tools well. Three independent read-only reviews (backend, browser, ecosystem) fed it. Where a claim was checked by
hand it says **verified**; everything else is the reviewers' reading and is marked as such.

## Verdict

The architecture is sound and should stay: a thin PHP endpoint that speaks a *subset* of the Algolia multi-query protocol
over Elasticsearch, driving **stock instantsearch.js widgets** from a Stimulus controller. The alternatives do not fit a
Symfony shop without a Node service: `instantsearch-elasticsearch-adapter` is dead (last push 2023), Searchkit wants a
Node/edge proxy and its ES 9 support is undocumented, Elastic's own Search UI is a React stack, and App Search /
Search Applications are deprecated.

The problems are in the details, and the user's instinct about the `.ais-*` classes is right.

## Done well: leave alone

- Lexical-mode faceting: `post_filter` plus per-facet filter aggregations that exclude a facet's own field give correct
  disjunctive counts (`ElasticsearchQueryBuilder.php:47,76-78`).
- Alias-based blue/green rebuild; bulk batching by count and bytes; one shared index-name resolver for read and write.
- HTML-encoded highlights (safe for `|raw`); the gateway's abuse limits and `public_searches` allowlist; API-key log redaction.
- `routing: true`, error handling, `dispose()`, `aria-live` on the stats target.
- The stock widgets themselves. The Twig/LiveComponent UI (absorbed ux-search) and the instantsearch.js UI cover different
  needs (server-rendered lists vs. instant search); retire neither yet.

## Recommended order

1. **`cssClasses` + one shared stylesheet** (about 1 day). Make the controller's widgets take Tabler/Bootstrap classes
   (`pagination` -> `pagination`/`page-item`/`page-link`; `refinementList` -> `form-check`/`form-check-input`; `sortBy` ->
   `form-select`), delete the per-app copies, stop loading `algolia.min.css`, move the empty-state and `<style>` hack out of the
   bundle. This removes the red flag.
2. **Remove live Meili JS** from global-giving and ssai (1-2 days each) and the 14 stale pins as each app moves.
3. **Gateway:** honour `params.facets` and `maxValuesPerFacet`, always emit `facets_stats` for range targets, accept AND
   groups, add `searchForFacetValues`, add a `historyRouter` with a short `stateMapping` (about 1 day).
4. **Analysis:** needs a design decision (below) before code.
5. **Index settings:** `number_of_replicas: 0` during bulk, configurable shards/replicas (2 hours); facet-only `keyword` type.
6. **Hybrid facets:** apply filters as `post_filter` in vector/hybrid modes; keep client-side RRF.
7. **Query tuning and new ES features:** `prefix_length`, phrase boost, `search_as_you_type`, highlight fragments; later
   the synonyms API, did-you-mean, and instantsearch.js's `autocomplete` widget (added in 4.82).
8. Bump instantsearch.js and friends to 4.119.0 everywhere (`bin/importmap-update` is production-only; edit the pins).

## Decisions needed

- **Languages per dataset** before item 4: which corpora are single-language (use that language's analyzer) and which are
  mixed (ICU folding plus language sub-fields)? Hindi needs its own normalization filters.
- ~~**Licence**~~ **Decided 2026-10-04 (Tac): stay on the free licence until major grant funding.** The native `rrf` retriever,
  `text_similarity_reranker`, Elastic Rerank and Learning to Rank are unavailable, so hybrid search stays on the
  client-side RRF fallback with `dense_vector` + `knn` (both work on the free tier). Plan around that, not around Enterprise.

## Unverified

- Whether ELSER / `semantic_text` work on the free self-managed tier (one source says Enterprise, the docs say "an appropriate
  license"). Test on our cluster before planning around it.
- Searchkit's ES 9 support; production cluster settings (only the local node was inspected); whether a newer 9.5.x PHP client
  patch exists; accessibility beyond labels (no screen-reader run).
- Environment facts: local ES 9.5.3 with `elasticsearch/elasticsearch` v9.5.0 in bench, zm and packages.
